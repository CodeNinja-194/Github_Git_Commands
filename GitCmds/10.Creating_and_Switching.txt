//  Creating, Switching, Merging, and Deleting Branches in Git

//  CREATING BRANCHES

1:  git branch branch_name
    //  Creates a new branch but doesn't switch to it
    //  Stays on current branch

2:  git branch
    //  Lists all local branches
    //  Current branch is marked with *

3:  git branch -a
    //  Lists all branches (local and remote)

4:  git branch -r
    //  Lists only remote tracking branches

5:  git branch branch_name commit_hash
    //  Creates branch from specific commit (not current HEAD)

6:  git branch -M new_name
    //  Renames current branch to new_name

7:  git branch -m old_name new_name
    //  Renames specific branch

//  SWITCHING BRANCHES

8:  git checkout branch_name
    //  Switches to existing branch

9:  git checkout -b branch_name
    //  Creates new branch and switches to it (one command)
    //  Most common way to create and start working on branch

10: git checkout -b feature/login origin/feature/login
    //  Creates local branch tracking remote branch
    //  Useful after pulling and wanting to work on remote branch

11: git switch branch_name
    //  Newer way to switch branches (Git 2.23+)
    //  Clearer intention than git checkout

12: git switch -c branch_name
    //  Creates and switches to new branch (newer way)

13: git switch -
    //  Switches to previously checked out branch
    //  Useful for toggling between two branches

//  MERGING BRANCHES

14: git merge branch_name
    //  Merges specified branch into current branch
    //  Creates a merge commit (unless fast-forward)

15: git merge branch_name --no-ff
    //  Forces merge commit even if fast-forward possible
    //  Better for preserving branch history

16: git merge branch_name --squash
    //  Combines all commits from branch into one
    //  Cleaner history but reverts branch record

17: git merge --abort
    //  Cancels ongoing merge if conflicts occurred

18: git merge -X ours branch_name
    //  Merges but prefers current branch's changes in conflicts

19: git merge -X theirs branch_name
    //  Merges but prefers incoming branch's changes in conflicts

//  VIEWING BRANCH INFORMATION

20: git branch -v
    //  Shows branch with last commit hash and message
    //  Helpful to see current status of branches

21: git branch -vv
    //  Shows branch with tracking info
    //  Shows which remote branch each local tracks

22: git branch --merged
    //  Shows branches already merged into current branch
    //  These can be safely deleted

23: git branch --no-merged
    //  Shows branches NOT yet merged into current branch
    //  Git warns if you try to delete unmerged branches

24: git log --oneline --graph --all
    //  Shows visual representation of branch history
    //  Great for understanding branch structure

25: git diff branch1..branch2
    //  Compares two branches
    //  Shows what changed in branch2 compared to branch1

26: git diff branch1 branch2
    //  Alternative syntax for comparing branches

//  DELETING BRANCHES

27: git branch -d branch_name
    //  Deletes branch (only if fully merged)
    //  Gives error/warning if not merged

28: git branch -D branch_name
    //  Force deletes branch without checking if merged
    //  WARNING: May lose commits!

29: git branch -d -
    //  Deletes previously checked out branch

30: git push -d origin branch_name
    //  Deletes remote branch

31: git branch -dr origin/branch_name
    //  Deletes local remote tracking branch

//  BRANCH MANAGEMENT

32: git branch -m old_name new_name
    //  Renames branch

33: git branch --track local_name origin/remote_name
    //  Creates local branch to track remote branch

34: git branch -u origin/main
    //  Sets upstream branch for current branch
    //  Links current branch to specific remote branch

35: git branch --set-upstream-to=origin/main
    //  Alternative syntax to set upstream

//  PRACTICAL WORKFLOW EXAMPLES

//  Example 1: Create and work on feature branch
//  1. git checkout -b feature/user-login
//  2. Make changes and commit
//  3. git push -u origin feature/user-login
//  4. Create PR on GitHub
//  5. After approval: git merge feature/user-login
//  6. git branch -d feature/user-login  (delete locally)
//  7. git push -d origin feature/user-login  (delete remotely)

//  Example 2: Switch between branches
//  1. git branch  (see all branches)
//  2. git checkout develop  (or git switch develop)
//  3. Make changes
//  4. git checkout - (switch back to previous branch)

//  Example 3: Merge feature branch into main
//  1. git checkout main  (switch to main)
//  2. git pull origin  (get latest)
//  3. git merge feature/new-feature  (merge feature)
//  4. git push  (push merged code)

//  CONFLICT RESOLUTION DURING MERGE

//  If conflicts occur:
36: git status
    //  Shows conflicted files

37: Edit conflicted files manually (remove conflict markers)

38: git add resolved_file
    //  Stage the resolved file

39: git commit
    //  Complete the merge with commit

40: git merge --abort
    //  Cancel merge if you decide not to proceed

//  BRANCH NAMING CONVENTIONS (Best Practice)

//  feature/feature-name    - new feature development
//  bugfix/bug-description  - bug fixes
//  hotfix/critical-issue   - urgent production fixes
//  develop                 - integration branch
//  main/master             - production-ready code
//  release/v1.0            - release preparation

//  NOTES:
//  - Always use descriptive branch names
//  - Delete merged branches to keep repository clean
//  - Use git branch -a to see all branches (local + remote)
//  - Use --merged to find branches safe to delete
//  - Merge only when branch is complete and tested
//  - Use --no-ff for important merges to preserve history
//  - Always pull latest before starting new work
//  - Avoid long-lived branches (merge frequently)
