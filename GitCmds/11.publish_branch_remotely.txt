//  Publishing Branches Remotely - Pushing to GitHub

//  BASIC PUSH OPERATIONS

1:  git push
    //  Pushes current branch to its tracking remote (usually origin)
    //  Only works if branch already has upstream set

2:  git push origin branch_name
    //  Pushes specific branch to origin remote
    //  Creates branch on remote if it doesn't exist

3:  git push -u origin branch_name
    //  Pushes branch and sets it to track origin/branch_name
    //  -u = --set-upstream (use on first push of new branch)
    //  After this, 'git push' alone will work for this branch

4:  git push --all
    //  Pushes all local branches to remote

5:  git push --tags
    //  Pushes all tags to remote

6:  git push origin --tags
    //  Pushes all tags to specific remote

//  PUSHING WITH CUSTOM REMOTE NAMES

7:  git push origin feature/login
    //  Pushes local 'feature/login' branch to remote with same name

8:  git push origin bugfix:mybugfix
    //  Pushes local 'bugfix' branch but names it 'mybugfix' on remote
    //  Useful if local and remote names should differ

9:  git push origin feature/new:develop
    //  Pushes feature/new branch to remote develop branch
    //  Helpful for merging into main branch on remote

//  DELETING REMOTE BRANCHES

10: git push -d origin branch_name
    //  Deletes branch from remote repository
    //  -d = --delete

11: git push origin --delete branch_name
    //  Alternative syntax for deleting remote branch

12: git push origin :branch_name
    //  Old syntax for pushing empty content to delete
    //  Still works but not recommended

//  FORCE PUSHING (Use with CAUTION!)

13: git push -f origin branch_name
    //  Force pushes (overwrites remote with local)
    //  -f = --force
    //  WARNING: Only use on personal branches!
    //  NEVER on shared branches (main, develop, etc.)

14: git push --force-with-lease origin branch_name
    //  Safer force push (fails if remote changed)
    //  Recommended over --force

15: git push -f origin branch_name
    //  If rebase happened and need to force update

//  FETCHING AND TRACKING REMOTE BRANCHES

16: git fetch origin
    //  Downloads branch info from remote
    //  Updates remote tracking branches

17: git checkout --track origin/branch_name
    //  Creates local branch tracking remote branch
    //  Git automatically sets up tracking

18: git checkout -b local_name origin/branch_name
    //  Creates local branch with different name tracking remote

19: git branch -u origin/branch_name
    //  Sets upstream of current branch to remote branch

//  KEEPING BRANCHES IN SYNC

20: git pull origin branch_name
    //  Fetches and merges remote branch into local

21: git fetch origin
    //  Downloads latest from remote without merging

22: git pull --rebase origin branch_name
    //  Fetches and rebases instead of merging

//  HANDLING COMMON ERRORS AND ISSUES

23: //  ERROR: failed to push - need to fetch first
    git pull origin branch_name
    //  Solution: Always pull before pushing

24: //  ERROR: rejected because of unmerged work
    git fetch origin
    git rebase origin/branch_name
    //  Then: git push origin branch_name

25: //  ERROR: refused to delete - not fully pushed
    git push -d -f origin branch_name
    //  Force delete if branches and commits are safe

26: //  ERROR: remote branch doesn't exist for checkout
    git fetch origin
    //  Updates remote tracking info
    //  Then: git checkout branch_name

//  WORKFLOW EXAMPLE: Complete Push Process

//  Step 1: Create and work on feature
//  git checkout -b feature/user-auth

//  Step 2: Make commits
//  git add .
//  git commit -m "Add user authentication"

//  Step 3: Push new branch with tracking
//  git push -u origin feature/user-auth

//  Step 4: On GitHub: Create Pull Request

//  Step 5: After review and approval:
//  git checkout main
//  git pull origin main
//  git merge feature/user-auth

//  Step 6: Push merged code
//  git push origin main

//  Step 7: Delete branch locally and remotely
//  git branch -d feature/user-auth
//  git push -d origin feature/user-auth

//  BRANCH PROTECTION AND CI/CD

27: //  Main/master branches often have protection rules
    //  GitHub enforces: require PR review, passing tests, etc.

28: //  If push is rejected due to branch protection:
    //  1. Create feature branch instead
    //  2. Push feature branch
    //  3. Create Pull Request on GitHub
    //  4. Get review and approval
    //  5. Merge via GitHub UI

//  VIEWING REMOTE BRANCHES

29: git branch -r
    //  Lists all remote tracking branches

30: git branch -a
    //  Lists all local and remote tracking branches

31: git remote -v
    //  Shows remote URLs

//  SETTING DEFAULT PUSH BEHAVIOR

32: git config --global push.default simple
    //  Only push current branch to remote with same name

33: git config --global push.default upstream
    //  Push to configured upstream branch

//  BEST PRACTICES

1. Always create feature branches, don't push to main
2. Use 'git push -u' on first push of new branch
3. Pull before pushing to avoid conflicts
4. Never force push to shared branches
5. Delete merged branches to keep clean
6. Write clear commit messages
7. Use Pull Requests for code review
8. Test locally before pushing
9. Keep branches focused on single feature
10. Merge frequently, keep branches short-lived

//  NOTES:
//  - origin = default remote name
//  - -u flag sets upstream tracking
//  - Always check branch before pushing
//  - Force push should be exception, not rule
//  - Use --force-with-lease for safer force push
//  - Deleted remote branches are also deleted in CI/CD
//  - Branch protection prevents direct pushes to main
